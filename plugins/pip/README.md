# pip

Four tool-call interrupt rules for Python repos that use `pip` and
`venv` directly — no uv, no Poetry, no Pipenv. They defend one property: the
environment you are working in can be rebuilt from what the repo declares.

| Rule | Fires on | Point |
|---|---|---|
| `pip-needs-a-virtualenv` | `sudo pip`, `pip install --user`, `--break-system-packages` | System and user-global `site-packages` are unreproducible and shared with OS tooling. Activate a venv, then check `$VIRTUAL_ENV` and `pip -V`. |
| `pip-pinned-requirements` | `pip install <pkg>` with no `-r`/`--requirement` and no version specifier | An undeclared install exists only in your venv. Add it to `requirements.txt` or `pyproject.toml`, then install from there. |
| `pip-requirements-files` | writes to `requirements.txt`, `requirements.in`, `requirements*.lock` | Compiled output is not source. The `# This file is autogenerated by pip-compile` header tells you which one you opened. |
| `pip-resolver-overrides` | `pip install` with `--no-deps`, `--force-reinstall`, `--ignore-installed` | Each hides a resolver conflict and leaves an environment the requirements file no longer describes. Fix the pin, or rebuild the venv. |

The three command rules are scoped `tool:bash`, so they fire on actual shell
execution — never on a `write`/`edit` that merely *mentions* one of these flags
in prose or a code block. Every flag pattern is anchored to a `pip install`
invocation, so a shared flag name on another tool (`npm install --force`,
`git push --force`) does not trip them. `pip-requirements-files` is a path rule
and fires when one of those files is written or edited.

Bootstrap installs of `pip`, `setuptools`, `wheel`, and `pip-tools` themselves
are deliberately exempt from `pip-pinned-requirements` — they provision the
environment rather than being dependencies of the project.

## Install

```sh
omp plugin marketplace add andyhite/omp-foreman
omp plugin install pip@omp-foreman
```

Independent of every other plugin in this marketplace — install it alone, with
others, or not at all.
